# 9日目の演習：チームの準備と Issue

説明ページ：[9日目：チームの準備と Issue](../../docs/day09-team-kickoff.md)

## 目的

チームリポジトリに参加してクローンし、役割を確認します。Issue を作ってやりとりし、チームのルールに合意します。

## 所要時間の目安

45〜60分（チームで集まる日です）

## 手順

> [!NOTE]
> `<...>` の部分は、かっこごと置き換えてから実行します。

1. 運営者から届いた招待を承認します（メール、または `https://github.com/<運営者のアカウント>/gitlearn-team-<チーム記号>/invitations`）。
2. チームリポジトリをクローンします。

   ```bash
   cd ~/git-practice
   git clone https://github.com/<運営者のアカウント>/gitlearn-team-<チーム記号>.git
   ```

3. GitHub ユーザー名のアルファベット順（大文字小文字は区別しない）で、自分の役割記号（A〜D）を決めます。チーム全員で確認し、下の表に記入する人（進行役の A）を決めます。

   | 役割記号 | GitHub ユーザー名 |
   |---|---|
   | A | |
   | B | |
   | C | |
   | D（3人チームなし） | |

4. 進行役（9日目は A）が、「チームのルール」Issue を作ります。本文には次の例文を使います。

   ```markdown
   ## チームのルール

   1. `main` に直接 push しない。作業は必ずブランチ → PR。
   2. ブランチ名は `<GitHubユーザー名>/<内容>` にする。
   3. PR は作成者以外の1人が Approve したら、作成者が「Create a merge commit」でマージする。
   4. マージしたら GitHub 上のブランチを削除し、手元は `git switch main` → `git pull` にする。
   5. 作業を始める前に `git switch main` → `git pull` で最新にする。
   6. 個人情報（本名のフルネーム、電話番号、住所、学籍番号、顔写真）は書かない。

   ## 役割

   | 記号 | GitHub ユーザー名 |
   |---|---|
   | A | |
   | B | |
   | C | |
   | D | |

   合意する人は「合意します」とコメントしてください。
   ```

   役割の表には、手順3で決めた記号とユーザー名を書き込みます。3人チームの場合は D の行を消します。

5. 全員が、その Issue に「合意します」とコメントします。
6. 自分用の Issue を、テンプレート「作業タスク」で作ります。

   - タイトル：`メンバー紹介ページを追加（<GitHubユーザー名>）`
   - やること：`members/` に自分の紹介ページを追加する
   - 完了条件：PR がマージされ、`main` に自分のページがある
   - 担当（Assignees）：自分
   - ラベル（Labels）：`documentation`

7. Issue 番号（`#3` のような番号）をメモします。10日目で使います。

## 完了条件

- [ ] `~/git-practice/gitlearn-team-<チーム記号>` があり、`git log --oneline` が表示される
- [ ] 自分の役割記号（A〜D）と、チーム全員の役割を把握している
- [ ] 「チームのルール」Issue に、自分の「合意します」コメントがある
- [ ] 自分担当の「メンバー紹介ページを追加」Issue があり、Assignees が自分になっている
- [ ] 誰かの Issue に、`@ユーザー名` のメンションか `#番号` の参照を含むコメントを1つ書いた

## ヒント

- 招待が見つからないときは、迷惑メールフォルダを見るか、上の `invitations` の URL を直接開きます。
- `git clone` で `Repository not found` などのエラーが出たら、招待を承認できているか確認してください。Private のリポジトリは、承認前は「見つからない（not found）」と表示されます。
- Public のリポジトリは、承認しなくてもクローンできてしまいます。それでも、承認しないと10日目の push で `403`（`Permission to ... denied`）になります。リポジトリのページ上部に招待の案内が出ていないか確かめてください。
- 質問や教材の誤りは、「質問」「教材の修正依頼」テンプレートで Issue にしても構いません。
